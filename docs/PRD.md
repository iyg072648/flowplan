# 📄 제품 요구사항 정의서 (PRD) - FlowPlan

## 1. 개요 (Overview)
* **프로젝트명:** FlowPlan (목표 달성을 위한 AI 기반 적응형 스터디 플래너)
* **문서 목적:** 본 문서는 FlowPlan 애플리케이션의 기획, 디자인, 개발, 테스트 등 프로젝트 전반에 걸친 핵심 요구사항을 정의하여 팀원 간 명확한 목표와 기능 명세를 공유하기 위함입니다.
* **타겟 사용자:** 
  * 방대한 분량의 전공 공부를 해야 하는 대학생
  * 체계적인 계획 수립과 일정 관리에 어려움을 겪는 수험생 및 취업 준비생
  * 유동적인 일정 속에서도 목표한 학습량을 채우고자 하는 직장인

## 2. 문제 정의 및 해결 방안
* **문제 (Problem):** 학습자가 세운 고정된 계획은 예기치 못한 일정 변경이나 진도 지체로 인해 쉽게 무너집니다. 계획이 한 번 틀어지면 이를 수동으로 다시 수정하는 과정이 번거로워 결국 학습 자체를 포기하게 됩니다.
* **해결 (Solution):** 학습자가 남은 기간과 목표 분량만 입력하면 AI가 매일의 Task를 자동으로 분할해주고, 계획이 밀렸을 경우 버튼 하나로 남은 일정에 맞게 **스케줄을 자동 재조정(Adaptive Rescheduling)** 해주는 스마트 플래너를 제공합니다.

## 3. 핵심 요구사항 (Core Requirements)
| 구분 | 기능명 | 설명 | 우선순위 |
| :--- | :--- | :--- | :---: |
| **핵심 1** | AI 스마트 목표 분할 | 교재 목차 이미지(OCR)나 텍스트 입력을 바탕으로 남은 기간에 비례해 매일의 학습량을 자동 분할하여 캘린더에 매핑합니다. | 🔴 High |
| **핵심 2** | 동적 스케줄링 (재조정) | 특정 일자의 학습 목표를 미달성했을 때, 사용자의 요청에 따라 미완료된 분량을 남은 기간에 균등 혹은 난이도별로 재분배합니다. | 🔴 High |
| **핵심 3** | 학습 몰입도 트래커 | 내장된 뽀모도로 타이머로 실제 집중 시간(순공 시간)을 측정하고, 누적 데이터를 기반으로 주간/월간 학습 통계를 시각화합니다. | 🟡 Med |

## 4. 상세 기능 요구사항 (Functional Requirements)

### 4.1. 사용자 계정 및 인증
* **FR-1.1 소셜 로그인:** OAuth 2.0을 활용하여 Google 및 Kakao 계정으로 간편하게 가입 및 로그인할 수 있어야 한다.
* **FR-1.2 프로필 관리:** 닉네임, 프로필 이미지, 기본 목표(예: 자격증, 수능 등)를 설정 및 수정할 수 있어야 한다.

### 4.2. 목표 등록 및 스케줄링
* **FR-2.1 목표 직접 입력:** 목표명, 총 학습 분량(페이지 수, 강의 수 등), 시작일, 종료일을 수동으로 입력할 수 있어야 한다.
* **FR-2.2 목차 이미지 인식 (OCR):** 교재의 목차를 사진으로 촬영하여 업로드하면, 챕터 제목과 분량을 텍스트로 자동 추출해야 한다.
* **FR-2.3 AI 스케줄 자동 생성:** 설정된 총 분량과 기간, 주간 학습 가능 요일을 기반으로 매일 수행할 Task를 자동 생성해야 한다. (OpenAI API 활용)
* **FR-2.4 스케줄 동적 재조정:** '일정 재조정' 버튼 클릭 시, 과거의 미완료 Task 분량을 합산하여 남은 학습 가능 일자에 재분배(업데이트)해야 한다.

### 4.3. 캘린더 및 Task 관리
* **FR-3.1 월간/주간 캘린더 뷰:** 생성된 Task를 달력 형태로 한눈에 볼 수 있어야 한다.
* **FR-3.2 Task 상태 관리:** 각 Task를 `시작 전`, `진행 중`, `완료` 상태로 체크할 수 있어야 한다.
* **FR-3.3 일일 할 일 목록 (To-Do List):** 오늘 해야 할 Task 목록을 대시보드 최상단에 제공해야 한다.

### 4.4. 학습 타이머 및 통계
* **FR-4.1 뽀모도로 타이머:** 25분 집중 / 5분 휴식 등 사용자 지정이 가능한 타이머 기능을 제공해야 한다.
* **FR-4.2 백그라운드 측정:** 앱이 백그라운드에 있을 때도 타이머가 정상적으로 동작하거나 시간을 계산해야 한다.
* **FR-4.3 시각화 대시보드:** 일간/주간/월간 누적 집중 시간과 목표 달성률을 막대/선 그래프로 시각화하여 제공해야 한다.

## 5. 비기능적 요구사항 (Non-Functional Requirements)
* **NFR-1 (성능):** AI 스케줄 생성 및 재조정 요청 시 응답 시간은 최대 5초를 초과하지 않아야 한다.
* **NFR-2 (사용성):** 모바일 기기(iOS/Android)에 최적화된 반응형 UI 또는 네이티브 앱 환경을 제공해야 한다.
* **NFR-3 (가용성):** AWS 등 클라우드 환경에 배포하여 99% 이상의 서버 가동률(Uptime)을 보장해야 한다.
* **NFR-4 (데이터 보존):** 사용자 스케줄 데이터는 실시간으로 클라우드 DB에 동기화되어 기기를 변경해도 유지되어야 한다.

## 6. 개발 환경 및 기술 스택
* **Frontend:** React Native (모바일) / React (웹 뷰 관리자)
* **Backend:** Node.js (Express)
* **Database:** MySQL
* **External APIs:** OpenAI API, Google Cloud Vision API
* **Deployment:** AWS EC2 & RDS, GitHub Actions (CI/CD)
