# ADR-0002: 데이터베이스 PostgreSQL에서 MySQL로 전환

## 1. 상태 (Status)
- **상태:** 승인됨 (Accepted)
- **결정일자:** 2026-10-07
- **작성자 / 의사결정자:** FlowPlan Team

## 2. 배경 및 문제 정의 (Context)
초기 기획 단계에서는 JSON 데이터 처리와 확장성을 고려하여 PostgreSQL을 기본 DB로 선정하였습니다. 그러나 로컬 개발 환경 구성의 용이성, 팀원들의 익숙도, 클라우드 호스팅 편의성 및 초기 서비스 규모(사용자/목표/할 일 관리)를 고려했을 때 가장 보편적이고 안정적인 RDBMS로의 전환 필요성이 제기되었습니다.

### 고려된 대안
1. **PostgreSQL 유지:** 다양한 데이터 타입(UUID 기본 지원 등) 및 고급 기능 지원하나, 로컬 세팅 환경 종속성이 높음.
2. **MySQL 전환:** 팀원 전반의 개발 경험이 풍부하고 로컬 설치 및 AWS RDS 구성이 용이함.

## 3. 결정 사항 (Decision)
FlowPlan의 메인 RDBMS로 **MySQL (v8.0 이상)**을 채택하기로 결정했습니다.
- 백엔드 드라이버를 `pg`에서 `mysql2`로 교체하였습니다.
- DB 스키마에서 UUID 타입을 `VARCHAR(36)`으로, 타임스탬프 기본값을 `CURRENT_TIMESTAMP`로 마이그레이션했습니다.

## 4. 영향 및 결과 (Consequences)
### 긍정적 영향 (Pros)
- 로컬 개발 환경 셋업 속도가 대폭 단축되고 운영 복잡도가 감소했습니다.
- Node.js 환경에서 `mysql2/promise` 커넥션 풀을 통한 안정적인 트랜잭션 처리가 가능합니다.

### 부정적 영향 및 한계점 (Cons & Trade-offs)
- 기본 UUID 데이터 타입 대신 문자열 `VARCHAR(36)`을 사용함에 따라 인덱스 크기가 소폭 증가하므로 고성능 인덱싱 관리가 요구됩니다.
